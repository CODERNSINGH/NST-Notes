Part B — Internet gateway & routing4 marks▸
  • Create igw-lab, then attach it to vpc-lab.
  • Create route table rt-public in vpc-lab, add route 0.0.0.0/0 → igw-lab.
  • Associate subnet-a only. subnet-b must stay on the main (default) route table.
The route table is the resource people forget to tag. Untagged = invisible to the grader, and a subnet with no visible routing reads as private — that silently costs the Part B marks even though the build looks fine in the console.

Note the shape here is the opposite of Q3's firewall lab: this one is wide open on purpose, because the goal is protocol experimentation, not access control.

The three servers, side by side▸

HTTP/1.1

Python's built-in server. One request at a time per connection — the baseline everything else improves on.

python3 -m http.server 8080
DevTools protocol → http/1.1

HTTP/2

Hypercorn + Quart, over TLS. Multiplexes many requests on a single connection — always needs HTTPS, hence the self-signed cert.

hypercorn server:app --bind :443 --bind :8443
DevTools protocol → h2

HTTP/3

Same Hypercorn setup, plus aioquic. Runs over UDP (QUIC) instead of TCP — faster handshakes, no head-of-line blocking.

+ --quic-bind :443 --quic-bind :8443
DevTools protocol → h3 (often on reload #2)

The browser learns about QUIC from an Alt-Svc header sent inside the HTTP/2 response — that's why the very first load can still show h2 before a reload flips to h3.

Sanity check from a second terminal: sudo ss -ulnp | grep -E '443|8443' should list both ports as UDP listeners.
